# One-off runs of S1 step 7

The runs behind three statements of [`reports/s1-fixes.md`](../../reports/s1-fixes.md) that no committed test repeats. Machine paths are replaced by `<repo>`, `<scratch>` and `<home>`. The scratch copy `negr1/` is `natives/` of the fix commit with one change: when `cm_load` or `cm_resume` is refused with `CM_ST_BUSY`, it writes `machine is busy` into the message first, as 5381504 did (`cm_free` writes nothing, as in 5381504).

| File | What |
|---|---|
| `tier0-negctl.log` | Tier 0 (`machine-test.sh windows-x86_64`, Windows 11) on the scratch copy. Three of the four checks of section 9 about refused calls fail: the host re-entry check (the message reads `machine is busy`), the check that the machine was not changed, and the new check, where 0 of 10 rounds keep the owner's message. The fourth, `cm_free`, `cm_resume` and `cm_load` from another thread while busy, passes, because it checks only the statuses. |
| `tsan_race.c`, `ubuntu-tsan2.sh` | A ThreadSanitizer harness for review finding R1, built with `-fsanitize=thread` on Ubuntu 26.04 against `machine.c` of the fix commit and against the scratch copy. It has the bios, the three refused calls and the leave hook of the new Tier 0 check, but not its gate: `t.block()` returns at once, and the hammer calls from the time the owner has entered it. So its calls can overlap the owner's render of a 60,000-byte error and its traceback, but nothing forces that. ThreadSanitizer needs no overlap in time: it reports the refused call's write and the owner's writes because no synchronization orders them. |
| `tsan-current.log`, `tsan-negctl.log` | The two runs of the harness: no report and 10 of 10 rounds intact with the fix; data-race reports with the scratch copy (the refused call's `msg_set` against the owner's `render_error`, `msg_append` and `append_traceback` writes), and 0 of 10 rounds intact. |
| `tier0-tsan.log`, `tier0-tsan.out`, `ubuntu-tsan.sh` | Why the harness: Tier 0 itself built with `-fsanitize=thread`. With the fix and with the scratch copy alike, it stops after the last check of section 2, before section 3 (the spec fuzz) prints its first check. The `.log` is the program's output (the same for both builds, so one is kept); the `.out` is the script's own output, where bash reports the segmentation fault and the script prints exit 139 and 0 TSan reports for each build. |
