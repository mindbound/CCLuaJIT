## 1. Goal and "done when"

### 1.1 Goal

CC:T events reach the bios on LuaJIT exactly as they reach it on Cobalt:
- `handleEvent(name, args)` resumes the bios coroutine with the name and the arguments, which become the results of `coroutine.yield`.
- The first yielded value becomes the event filter when it is a string or a number (F9).
- An event whose name is not the filter, other than `terminate`, returns `OK` without a native call.
- `args == null` means no arguments.

This bios runs the same on both machines:

```lua
local got = ""
local function rec(name, ...) got = got .. name .. ":" .. select("#", ...) .. ";" return name end
while rec(coroutine.yield("ping")) ~= "terminate" do end
error(got, 0)
```

| Call | Result |
|---|---|
| `handleEvent(null, null)` | `OK` |
| `handleEvent("pong", {1})` | `OK`. The event is filtered, so no native call is made and Lua sees nothing. |
| `handleEvent("ping", {1, null})` | `OK` |
| `handleEvent("terminate", null)` | `error`. The first line is `ping:2;terminate:0;`, and the second line is `stack traceback:`. |

## 2. Scope

### 2.1 In S2

- **Event record:** `Wire.event` in Java and `wire_check_event` in C. One wire record, with no new value tag. `CCLJ_ABI` goes from 2 to 3.
- **Native delivery:**
  - `cm_resume` checks the record and refuses a bad one before any Lua call.
  - `resume_body` step 5 pushes the values onto `L` above `co`, then calls `lua_checkstack(co, n + 1)` and `lua_xmove`.
  - It then calls `lua_resume(co, n)`.
- **Filter:**
  - On YIELD, C writes a filter record into the message (§4.1).
  - `NativeMachine.resume` reads it on every YIELD (D24).
  - `LuaJITMachine` keeps it and applies Cobalt's rules: closed check first, `terminate` always passes, a null name skips the filter and ignores the arguments.
  - A number filter is converted with `tostring` in C (D25).
- **Patch 05 (D34 (c), §4.8):** `nd_round` rounds every exact decimal tie half up, as Cobalt does. This changes the text of a tie in every `tostring`, number concatenation and `lua_tolstring` of a number, not only in filters. It also changes `string.format`'s `%e`, `%f`, `%g`, `%s` and `%q` of a number. Each changed text becomes Cobalt's text, except `%q`, whose form differs from Cobalt anyway (F26, §4.8). `string.format` then differs from C `printf` and PUC Lua on exact ties.
- **Patch 05, `%f` (D35, §4.9):** `nd_div2k`'s digit limit for `%f` is back. Upstream turned it off in 7152e154, and `%f` of a number with about 560 or more fraction digits (every double below about 1e-171, and most below about 5e-153) has printed garbage since then: `string.format("%.0f", 1e-160)` gave `22772133350372314`. It now gives `0`, as on Cobalt and with C `printf`.
- **Drops (D19, scoped by D30):** Java drops an event before `nResume` when:
  - it has more than 7,998 arguments;
  - its record is over 16 MiB;
  - reading its arguments throws.

  The result is `OK`, one WARN is logged, and the filter is unchanged.
- **Event values:**
  - `null`, `Boolean`, `Number` (−0.0 is sent as +0.0, D29), `String` (Latin-1), `byte[]` and `ByteBuffer` (remaining bytes; the position advances).
  - `Map`, `Collection`, `Object[]`, method objects (D27) and unknown types become nil, with one WARN per class (D28).
- **Removal of the S1 refusal:** in C (`machine.c:988-990`), in Java (`LuaJITMachine.java:131-135`), and their documentation.
- **Tests:** Tier 0, Tier 1, Tier 2 and Option B, including two new `CCLJ_TEST` hooks.

### 2.3 Corrections to the S2 row (M1.md:1044) and related plan text

1. **"`nResume` copies the event" is already built.**
   - S1 step 3 built it: `jni_machine.c:187` copies the array, and `:205` passes it on (M1.md:477, :493).
   - S2 changes only the comments of `nResume` (`jni_machine.c:172-176`) and `nMessage` (`:214-217`). After a YIELD, the `nMessage` bytes are the filter record, and a NULL array there becomes `ST_INTERNAL`. No JNI code changes.
2. **The bound "`lua_gettop(co)` is 0 after every YIELD" (M1.md:362) does not cover the first resume.**
   - On `CM_NEW` the bios function is on `co`: `lua_gettop(co) == 1` (`machine.c:947`; `machine_test.c:1197-1200` checks it).
   - So C must allow 7,999 values after a YIELD but only 7,998 on the first resume (F23).
   - A single fixed bound would let a first-resume event of 7,999 values reach `lua_checkstack(co, 8000)`, whose size test (`lj_api.c:104`) returns 0. The machine would then be reported as a failed growth, not as INTERNAL.
   - CC:T's first call is `handleEvent(null, null)` (`CE:418`, `:476`, `:519`). It sends an event first only in the TURN_ON race of F23 (`CE:198`, `:473`, `:489-492`). So CC:T reaches this case only through that race.
3. **The filter has no path to Java.**
   - NOW, `NativeMachine.resume` never calls `nMessage` on YIELD (`NativeMachine.java:160`), and `Outcome.message` is documented as null for YIELD (`:49-50`).
   - The planned "message = filter" (`cclj_machine.h:56`, `:119`; M1.md:194) cannot tell "no filter" from the filter `""`, because YIELD writes an empty message (`machine.c:952`).
   - Cobalt treats `""` as a real filter (F24).
   - S2 defines a filter record (§4.1, D24).
4. **The rule for `co` and §3.8 disagree.**
   - The rule for `co` (M1.md:375-383; `machine.c:15-18`) does not list `lua_tonumber`.
   - §3.8 allows `lua_tonumber` "anywhere, including a dead `co`" (M1.md:451).
   - A number filter needs `lua_tonumber(co, 1)`. S2 adds `lua_tonumber` on a `LUA_TNUMBER` to the rule (§4.7).
5. **The 64 KiB cut of a filter.**
   - `CM_MSG_MAX` is documented as "error/filter text is cut to this" (`cclj_machine.h:74`; M1.md:210). Cobalt never cuts a filter (F24).
   - S2 never cuts a filter. A longer one is decided by D26.
6. **The 16 MiB event size is not handled.**
   - NOW, an event that `copy_array` refuses (`jni_machine.c:115`) gives INTERNAL. `NativeMachine.resume` then frees the machine with `CCLuaJIT: the machine could not be resumed (status 4)` (`NativeMachine.java:164-168`), as `BridgeProbe.java:336-341` asserts.
   - That contradicts D19's "drop, WARN, `OK`". S2 checks the size in Java (D30).
7. **D19's "cannot be converted" is undefined after the row's nil rules.** The row maps every type to a value. What is left is the count, the size, and a `Throwable` from addon code (D30).
8. **Method objects in events are not covered by the row** (D27). NOW, `unknown()` throws `UnsupportedValue` for them (`LuaJITMachine.java:229-232`). That throw is meant for a host call, and an event has no Lua caller.
9. **The row says both "one WARN per type" and "one WARN per class".** NOW, the code has one JVM-wide set of classes, with a method-result text (`LuaJITMachine.java:55-56`, `:237-238`). See D28.
10. **The gate contradicts the plan's own deviations.**
    - The S2 row says "Zero deviations from Cobalt", and §2 (M1.md:80) says "Differential event specs clean".
    - Yet the row itself plans these deviations: 7,999 arguments are dropped, `Map`/`Collection`/`Object[]` become nil, and D19 drops events.
    - D31 rewords the gate.
11. **`ByteBuffer` handling.**
    - The row says "its remaining bytes". DESIGN.md:231 and Cobalt (`CLM:188-191`) also advance the position.
    - Cobalt converts only after the filter test (`CLM:125` comes before `:130`), so a filtered `paste` event keeps its bytes. S2 does both.
12. **Tests the row omits:**
    - Tier 1 cases, although §4 requires Tier 0/1/2 (M1.md:1037-1040).
    - A fuzz test of the event checker, although §3.6 makes the C checkers fuzz targets (M1.md:281).
    - Malformed event bytes, the open item at `reports/s1-review-guide.md:343`.
    - The S1 tests to replace: `machine_test.c:1232-1267`, `BridgeProbe.java:328-335`, `MachineSpecs.java:415` and `:434-457`.
13. **ABI.** The row does not mention the ABI. S2 changes what `nResume` accepts and what a YIELD message means, so `CCLJ_ABI` goes to 3 (`cclj_machine.h:52`; `NativeMachine.java:62`). Step 7 set the precedent (M1.md:191, :539).
14. **Position of the hook point.**
    - The S2 hook comment sits before the F4 check (`machine.c:936-937` comes before `:940-943`).
    - M1.md:361 orders the push after step 4.
    - S2 pushes after the F4 check.
15. **A stale cross-reference.** `machine_test.c:1211` cites "resume_body step 3" for the size bound. The bound is step 5 (M1.md:361-362).
16. **−0.0 is not in the row.** Cobalt delivers it as integer 0. LuaJIT keeps the sign, which `1/x` shows (F25, D29).
17. **The GC point named at M1.md:359 ("in S2 the event push").**
    - No Lua code runs between `lua_rawgeti(L, LUA_REGISTRYINDEX, co_ref)` (`machine.c:929`) and the push.
    - So during the push the registry still refers to `co`, and a GC cycle cannot free it.
    - S2 keeps `co` at `L` index 1 as the rule says. It needs no extra GC test for that reason, but adds one for the pushed values (§6.1, item 11k).
    - The post-resume allocation that relies on `co` at `L` index 1 is the number-filter conversion (`yield_filter`), as `render_error`'s is. Item 11k tests it too.
18. **A failed push is ERROR without a traceback.** `LuaJITMachine` logs it as `Top level coroutine errored: …` (`LuaJITMachine.java:164-171`), although it is not a Lua error. Tier 2 lists it in `noTraceback` (`MachineSpecs.java:138`).
19. **`CM_ST_INTERNAL` is documented as "dead"** (`cclj_machine.h:59`). The S1 refusal leaves the C machine as it was (`machine.c:988-990`; checked at `machine_test.c:1243-1245`). S2 states that a refusal before any Lua call changes nothing in C (I10), and that Java frees the machine anyway (`NativeMachine.java:174-178`).
20. **A stale order note in M1.md.** M1.md:657 (step 4: "logged, then `close()`") contradicts M1.md:640 and the code (close first, `LuaJITMachine.java:144-153`). Fix it in the M1.md edit of step 6.
21. **Option B uses a `String`.** The row queues `char` with `"a"`, while CC:T's real `char` carries `byte[]{c}` (`cct-src/.../input/EventComputerInput.java:38`). B4 queues both.

### 4.1 Wire records (format stays v1; ABI 3)

S2 adds two records and no value tag:

```
event   := u32 n, value*n          Java -> C, nResume. 1 <= n; the first value is a STRING (the name);
                                   n <= CM_EVENT_MAX (7,999) after a YIELD, n <= 7,998 on the first resume;
                                   at most CM_WIRE_MAX (16 MiB) in all
filter  := (no bytes)              the message after CM_ST_YIELD: no filter
         | 04 u32 len, bytes       STRING: the filter, whole (len <= CM_FILTER_MAX = 65,531)
         | 01                      FALSE: a filter longer than CM_FILTER_MAX; only "terminate" passes (D26)
```

- `nMessage` sends the filter record as it sends any message: `u32 0xFFFFFFFF`, then the record. `msg_tb` is always `SIZE_MAX` on YIELD (M1.md:398). The `nMessage` code does not change (`jni_machine.c:218-250`), and J5 holds because the record is at most `CM_MSG_MAX` bytes.
- Example: `handleEvent("char", {"a"})` gives `02000000 04 04000000 63686172 04 01000000 61` (19 bytes).
- Example: `coroutine.yield("key")` gives the message `04 03000000 6b6579`, and `nMessage` gives `FFFFFFFF 04 03000000 6b6579`.
- A number filter is sent as a STRING. The bytes are exactly what `tostring(v)` gives in the bios under patch 05 (F26):
  - `%.15g` when it round-trips, else `%.17g`, with an exact tie at the 17th digit rounded half up (D34 (c));
  - −0 as `0`;
  - NaN as `nan`;
  - the infinities as `inf` and `-inf`.

  For example, `5` gives `5`, `0.1+0.2` gives `0.30000000000000004`, `1e14` gives `100000000000000`, `1e15` gives `1e+15`, `2^53` gives `9007199254740992`, and `391.786041259765625` gives `391.78604125976563`.
- The empty message means "no filter". So a YIELD without a filter still has an empty message, as in S1, and the S1 Tier 0 checks of an empty YIELD message (`machine_test.c:1198`) stay valid.

**`wire_check_event(d, len, &n)`** (`UNPROTECTED`, pure, a Tier 0 fuzz target, next to `wire_check_reply`):
1. Read `rd_u32`. Refuse `n == 0` or `n > r.left`, because every value takes at least one byte.
2. The first `rd_value` must be a STRING.
3. Read `n − 1` more values with `rd_value`, which refuses unknown tags and lengths past the end (`machine.c:323-343`).
4. Require `r.left == 0`.
5. Then set `*n` and return 1.

The value bound belongs to `cm_resume`, because it depends on the state.

**`msg_filter(m, s, n)`** (`UNPROTECTED`, pure):
- It sets `msg_tb = SIZE_MAX`.
- If `n > CM_FILTER_MAX`, `msg` is the single byte `CM_WIRE_FALSE` (D26).
- Otherwise `msg` is `CM_WIRE_STRING`, the 4-byte little-endian `n`, then the `n` bytes, so `msg_len = 5 + n`.
- It never cuts.

**`filter_number_body(L)`** (`PROTECTED`; the body of a nested `lua_cpcall`; the `number_body` pattern, `machine.c:794-804`):
1. `m = machine_of(L)`. If it is NULL, raise `CCLuaJIT: machine missing`.
2. `lua_pushnumber(L, m->err_num)`.
3. `s = lua_tolstring(L, -1, &n)`. This converts the copy it pushed (M1.md:453, F27).
4. `msg_filter(m, s, n)`, then return 0. Only "not enough memory" can be raised.

**`yield_filter(m, L, co)`** (`PROTECTED`; called by `resume_body`; it raises nothing itself). It reads `co` only through calls the rule for `co` allows (§4.7):
- If `lua_gettop(co) < 1`, set an empty `msg` (no filter).
- `LUA_TSTRING`: `s = lua_tolstring(co, 1, &len)`, which needs no allocation; then `msg_filter`.
- `LUA_TNUMBER`:
  1. `m->err_num = lua_tonumber(co, 1)`.
  2. `top = lua_gettop(L)`.
  3. If `lua_cpcall(L, filter_number_body, m) != 0`, then (D25):
     - `msg_from_top(m, L)`, which gives `not enough memory`;
     - `m->state = CM_DEAD`;
     - `m->result = CM_ST_ERROR`.
  4. `lua_settop(L, top)`.
- Any other type, including nil, booleans, tables, functions, threads and userdata: an empty `msg` (no filter).

    m->in_event = NULL; m->in_event_len = 0; m->in_event_n = 0;      /* I12: no pointer into nResume's copy */

  }
  machine_leave(m);                                                  /* every path after a successful enter */

### 4.5 Java

**`Wire`** (JDK-only; package `natives`):

```java
/** Arguments that can go with an event name: CM_EVENT_MAX - 1 (cclj_machine.h), the 8,000-slot limit (F23). */
public static final int MAX_EVENT_ARGS = 7998;
/** The largest record the native side copies (CM_WIRE_MAX). */
public static final int MAX_BYTES = 16 << 20;

/** An event dropped before nResume (D19, D30). Its message is the reason for the log. No stack trace. */
public static final class Dropped extends RuntimeException { … }

/** The filter of a YIELD. "terminate" always passes; otherwise the name must equal text, unless onlyTerminate. */
public record Filter(String text, boolean onlyTerminate) {
    public boolean passes(String name) { return name.equals("terminate") || (!onlyTerminate && name.equals(text)); }
}

public static byte[] event(String name, Object[] args /* null: no arguments */, Consumer<Object> onUnsupported)
public static Filter filter(byte[] raw)   /* null result: no filter */
```

`event` works in this order:
1. **Count, before any argument is read.** If `args.length > MAX_EVENT_ARGS`, throw `Dropped("it has <n> arguments, and at most 7998 fit")`. Nothing is converted, so no `ByteBuffer` moves and no callback runs.
2. Write `u32 (1 + args.length)`, then the name as a STRING (Latin-1, `c < 256 ? c : '?'`, as `Writer.latin1`, `Wire.java:369-377`).
3. **Each argument:**
   - `null` → NIL. Trailing nulls are kept and counted.
   - `Boolean` → TRUE or FALSE.
   - `Number` → NUMBER of `doubleValue()`, with −0.0 written as +0.0 (D29; the same writer helper as `values`).
   - `String` → STRING, Latin-1.
   - `byte[]` → STRING, copied as it is.
   - `ByteBuffer` → STRING of `remaining()` bytes, copied with `get`. The position advances, as in Cobalt (F28). Never use `array()`: the `paste` buffer is read-only.
   - `Map`, `Collection`, `Object[]` and any other type → `onUnsupported.accept(v)`, which may throw; then NIL.
4. **Size.** The writer throws `Dropped("its record is over 16 MiB")` only when `len + n > MAX_BYTES`, before it copies anything. Here `len` is the bytes written so far, and `n` is the bytes to add. It caps a doubled capacity at `MAX_BYTES`, as `Writer.room` caps it below `Integer.MAX_VALUE` now (`Wire.java:334-343`).

`values` (method results) keeps its S1 rules, except D29.

`filter` decodes an `nMessage` array:
1. Require at least 4 bytes and the offset `0xFFFFFFFF`.
2. Then:
   - no more bytes → null;
   - exactly one STRING → `Filter(text, false)`, Latin-1 decoded;
   - exactly the single byte FALSE → `Filter("", true)`;
   - anything else, also a null array or bytes left over → `IllegalStateException`.

- After the commit, the 46,000 random `string.format` results of a probe from the spec's third review equal Cobalt's saved output. Of its 49 chosen cases, only `%.1a` differs, as this section says. The review of this commit ran the same probe, and §4.9 calls it the probe of the D34 commit's review.
- The review of this commit found the `%f` bug that D35 fixes (§4.9).

### 4.9 Patch 05: the `%f` digit limit (D35)

**Found.** The review of the D34 commit (49d446e) found that `%f` prints garbage for a double whose exact decimal expansion has 559 or more fraction digits (568 or more when the low 32 bits of its mantissa are zero). That is every double below 2^-568 (about 1.0e-171), and most doubles below 2^-506 (about 4.8e-153), such as 1e-160 and 2e-153. A short binary fraction such as 2^-520 prints right. `string.format("%.0f|%.3f|%f", 1e-160, -1e-200, 2^-1074)` gives `22772133350372314|-287445976335078589.119|906459071.863478`. Cobalt and C `printf` give `0|-0.000|0.000000`. D34 did not cause it: the build before D34 prints the same.

**Cause.**
- Upstream 7152e154 (2025-12-08, "Fix string.format for limited precision FP conversions", LuaJIT #1363) added `nd_round` with its round-to-even test. That test reads every digit past the rounding digit, so the same commit turned off `nd_div2k`'s digit limit for `%f`: the line `stop1 = 63 - (int32_t)STRFMT_PREC(sf) / 9;` became a comment (`lj_strfmt_num.c:172-174`).
- `nd` is a ring of 64 limbs of 9 decimal digits each. The caller loads the mantissa into `nd[0]`, or into `nd[0]` and `nd[1]` when its low 32 bits are not zero, and `nd_div2k` then divides by the power of two. Without the limit, `nd_div2k` keeps every fraction limb. When the expansion needs 63 fraction limbs (559 or more digits) in the second case, or 64 (568 or more) in the first, the low fraction limbs wrap around into `nd[1]` or `nd[0]`, which `%f` prints as the integer part.
- Every LuaJIT v2.1 since 7152e154 has the bug: the vendored 047efd3b, a build of upstream with no CC patch, and the patch stack before and after D34. A 2023 build prints `0`.

**The change.**
- `stop1 = 63 - (int32_t)STRFMT_PREC(sf) / 9;` is code again. Its comment becomes "CC: upstream turned this limit off to round to even (7152e154), so %f of a number with about 560 or more fraction digits, such as 1e-160, wrapped around nd. nd_round rounds half up (S2, D34) and reads no digit past the rounding digit: the limit is back (S2, D35)."
- `stop1` is the limb that holds the rounding digit, for every precision from 0 to 99 (the most `string.format` accepts). The 9-bit loop of `nd_div2k` drops each carry below `stop1`. The dropped carries add up to less than one unit of `stop1`, so every digit in `stop1` and above stays exact. The last step, of fewer than 9 bits, still writes one limb below `stop1`, and the digits of that limb are not exact. No code reads that limb: `nd_round` reads only the rounding digit, which is in `stop1`, and the `%f` printer reads at most ceil(prec/9) fraction limbs, none of them below `stop1`. So the result is exact.
- With the limit, the live part of the ring spans at most 15 limbs, because `stop1` is at least 52.
- The `%e` and `%g` branch of the same `if` keeps its limits (`stop1`, `stop2`), as upstream has it.
- With D34, `nd_round` rounds as both callers did before 7152e154, when they added 5·10^e directly. D35 restores the other half of that commit. A build with that direct add in place of `nd_round` prints byte-identical output on the corpora below.

**Evidence.**
- Exact reference: 2,190,000 conversions, compared with Python's `decimal` under `ROUND_HALF_UP`. Five seeds of 6,000 doubles each (normals, subnormals, short binary fractions, decimal ties and huge values, a quarter of them negated), each under `%.0f` to `%.20f`, `%.0e` to `%.20e`, `%.0g` to `%.20g`, `%.99f`, `%.99e`, `%.40g`, `%f`, `%e`, `%g`, `%#.3g`, `%#.0e`, `%#.0f` and `tostring`. With D35: 0 mismatches. Without it: 138,408, all of them `%f` of numbers below 2.1e-153.
- The review of D35 added 1,314,000 conversions of the same kind (three new seeds) and 10,490,304 adversarial ones: values near 2^-k for every k from 1 to 1074, near 10^-j for j from 140 to 170, exact ties at every precision from 0 to 99, large integer parts and subnormals, under `%.0f` to `%.99f` with flags and widths, and `%e` and `%g` up to precision 99. With D35: 0 mismatches. A build without D35 fails 813,600 of the adversarial ones.
- Cobalt prints the same text as the build with D35 for: `%.0f %.3f %f` of 1e-160, 1e-200 and 2^-1074; the same negated; `%.0f %.2f %.20f %g %.3e` of 1e-153, 1e-154, 3e-160, 1e-160 and 1e-160; `%.99f` of 2^-1074; and `%.0f %.1f %.5f` of 2^-1022, 0.05 and 1e-6.
- The probe of the D34 commit's review (46,000 random `string.format` results and 49 chosen cases) prints the same with and without D35. The harnesses pass.

**Tests.**

- Scenario 49 gains an eighth group with the same format, differential: Cobalt gives `0 -0.000 0.000000`.
